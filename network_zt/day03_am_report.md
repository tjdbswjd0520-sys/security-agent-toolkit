Address:  168.126.63.1

  - 쓸 내용: 에러 이름은 마지막 줄의 `:` 앞부분 하나, `nslookup` 문구는 `Non-existent domain` 이 든 줄 하나(맥북은 `NXDOMAIN` 이 든 줄)

  socket.gaierror,

  - 쓸 내용: ① (가-1) 첫 줄의 리스트를 0 번부터 세어 각 칸에 무엇이 있는지 ② `//` 사이에 무엇이 생겼는지
  - 답:parts[0] == 'https:'이다. parts[1]은 '/'과 '/' 사이에 있는 내용인데 아무것도 없으므로 공백이고, 두 번째 '/'다음에 오는 내용이 'nowhere-not-exist.com이므로 parts[2]는 도에인 이름이 나오게 된다.
- (나-2) 두 번째 파일은 왜 마지막 줄에서 에러가 나며 멈췄을까요? `nslookup` 결과와 이어서 적어 주세요.
  - 쓸 내용: ① `gethostbyname()` 이 DNS 서버에 무엇을 물었는지 ② DNS 서버가 어떤 답을 했는지 ③ 그래서 왜 에러가 났는지
  - 답:DNS 서버에서 abc.nowhere-not-exist.com을 찾지 못해 IPv4주소를 리턴하지 못했기 때문에 출력할 값이 없어 에러가 났다.
- (다) 🔍 `Non-existent domain`(NXDOMAIN) 이 나왔다고 인터넷이 끊긴 걸까요? 아니라면 왜 아닌지 적어 주세요.
  - 쓸 내용: ① DNS 서버가 답을 했는지 안 했는지 ② 인터넷이 정말 끊겼다면 화면이 어떻게 달랐을지
  - 답: 서버는 'NXDOMAIN' 이라는 답변을 내놓았다. 끊긴 것이 아니다. 만약 인터넷이 끊겼다면 DNS서버에 접근조차 하지 못했을 것이다.

## 4교시 · 레코드와 캐시

### 문제 4-1 · 메일 서버와 별칭 — MX · CNAME

- (가-1) `nslookup -type=mx google.com` 에서 메일 서버 이름(`mail exchanger =` 뒤)과 우선순위 숫자(`MX preference`)를 적어 주세요.
  - 쓸 내용: 메일 서버 이름 하나, 숫자 하나. 아래에 같이 나오는 IP 는 적지 않습니다
  - 답:smtp.google.com, 10.
- (가-2) `nslookup www.naver.com` 에서 `Aliases:` 줄의 이름과 `이름:` 줄의 최종 이름을 적어 주세요.
  - 쓸 내용: `Aliases:` 에 나온 이름, `이름:` 에 나온 이름. 맥북은 `canonical name =` 뒤가 최종 이름입니다
  - 답: www.naver.com
- (나-1) MX 레코드는 왜 IP 가 아니라 서버 이름으로 답할까요? 그 서버의 IP 는 어떻게 알아낼까요?
  - 쓸 내용: ① 서버 이름으로 적어 두면 좋은 점(서버 IP 가 바뀌는 경우를 생각해 보세요) ② IP 를 알아내는 방법(안내 4.1 절의 표 참고)
  - 답: mx레코드가 답한 메일 서버 이름을 A 레코드나 AAAA 레코드에 조회하여 IP주소를 알아낸다. 따라서 메일 서버의 ip주소가 바뀌더라도 mx레코드를 바꿀 필요가 없기 때문이다. 
- (나-2) `www.naver.com` 은 왜 다른 이름(정식 이름)을 가리키고 있을까요?
  - 쓸 내용: ① CDN 이 무엇인지 한 줄 ② 큰 사이트가 CNAME 으로 CDN 이름을 가리키게 하는 까닭
  - 답:CDN이란 전 세계에 분산된 캐시 서버를 통해 사용자에게 가장 가까운 웹 콘텐츠를 전달하는 기술이다. 트래픽이 몰리는 사이트의 경우 사용자의 접속 위치나 네트워크 위치에 따라 최적의 CDN 서버로 유도해야 할 필요가 있기 때문이다.
- (다) 🔍 의심스러운 메일을 받았을 때, 보낸 쪽 도메인의 MX 레코드를 확인하면 무엇을 알 수 있을까요?
  - 쓸 내용: ① 정상 회사 도메인의 MX 는 보통 어떤지 ② MX 가 없거나 낯설면 무엇을 의심할 수 있는지
  - 답: 기업은 대게 자체 메일 서버나 신뢰할 수 있는 외부 메일 서비스의 유효한 MX 레코드를 등록해둔다. MX가 등록한 것과 다를 경우 도메인 사칭이나 이메일 변조 등을 의심해볼 수 있다.

  - 답: 만료 시각이 지나 캐시가 사라진 두 번째 파일에서는 새롭게 캐시를 저장해야 하기에 DNS서버에 묻는 것이고 만료 시각이 지나지 않아 캐시가 사라지지 않은 첫 번째 파일에서는 존재하는 캐시의 답을 그대로 사용할 수 있기에 캐시의 답을 쓴다는 출력이 나오는 것이다.
- (다-1) 🔍 사이트가 서버 IP 를 바꿨는데도, 한동안은 옛 IP 로 접속되는 사람이 있습니다. 왜 그럴까요?
  - 쓸 내용: ① 캐시에 무엇이 저장되는지 ② TTL 이 지나기 전에는 어떻게 동작하는지
  - 답: 캐시에는 도메인-ip 매핑 정보가 저장되는데, ttl이 지나가기 전에는 기존 캐시를 우선적으로 사용하기 때문에 옛 ip로 접속되기도 한다.
- (다-2) 어떤 PC 가 계속 이상한 주소로 접속된다면, 관제 담당자는 왜 `ipconfig //flushdns` 부터 해 볼까요?
  - 쓸 내용: ① 캐시에 어떤 답이 남아 있을 수 있는지 ② 비운 뒤에는 PC 가 어떻게 다시 묻는지
  - 답: 컴퓨터는 한 번 방문한 웹사이트의 도메인 이름과 그 ip주소를 DNS 캐시에 임시저장한다. ipconfig //flushdns 로 캐시를 비우면 저장되어 있던 도메인-IP 매칭 정보가 전부 사라져 기존 경로로 연결할 수 없게 되며, 컴퓨터는 DNS서버에 다시 IP주소를 물어 새로운 매칭 정보를 가져온다. 이러한 이유로 관제 담당자는 ipconfig //flushdns를 이용해 경로를 바꾸는 것이다.
