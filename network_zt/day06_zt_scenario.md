# A사 Zero Trust 적용 방안
## 5대 원칙 적용 방안
- ID:모든 직원과 서비스 계정에 개인별 계정을 부여하고, 퇴사자의 계정은 즉시 비활성화한다. 관리자 계정과 외부 접속 계정에는 MFA를 필수 적용한다.
- Device:등록된 회사 기기만 업무 시스템에 접속하도록 제한한다. 백신 미설치, 보안 패치 미적용, 기기 상태 이상이 확인되면 접속을 차단하거나 격리한다. 등록되지 않은 NB-7741과 같은 기기는 등록 및 보안 상태 확인 전까지 접근을 허용하지 않는다.
- Network: 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다
- Application:부서별 역할에 따라 사용할 시스템과 데이터 범위를 제한한다. 영업팀은 SALES, 재무팀은 SETTLE에 접근하도록 하고, 다른 부서의 데이터 접근은 별도 승인이 없는 한 거부한다. 계정 관리 기능은 account_admin 역할에만 허용한다.
- Policy:접속 시간, 국가, MFA 수행 여부, 기기 보안 상태, 조회 건수와 반복 패턴을 평가한다. 위험 점수가 10점 이상이면 추가 인증 또는 담당자 확인을 요구하고, 50점 이상이면 요청을 거부한다. 단, 업무별 위험도에 따라 기준을 조정하고 반복 조회는 누적 집계한다.
## 판단과 집행
- PDP(결정):중앙 접근 정책 서버에 둔다. 사용자 신원, 기기 상태, 역할, 접속 위치와 위험 점수를 확인해 허용·추가확인·거부를 결정한다.
- PEP(집행):업무 포털 앞의 접근 게이트웨이, 서버 방화벽 및 애플리케이션의 인증·인가 지점에 둔다. PDP의 결정을 실제로 적용해 허용되지 않은 연결과 데이터 요청을 차단한다.
## 흐름도
```
사용자·기기
    │ 요청
    ▼
PEP (접근 게이트웨이)
    │ 판단 요청
    ▼
PDP (중앙 정책 결정 서버)
    │ 신원·기기·역할·위험도 평가
    │ 허용 / 추가확인 / 거부
    ▼
PEP (결정 집행)
    │
    ├─ 허용 → 승인된 시스템에 접근
    ├─ 추가확인 → MFA 또는 담당자 확인
    └─ 거부 → 접근 차단 및 기록
```
## 최소권한 기준 (목록에 없으면 거부)
- 재무팀:정산 시스템 SETTLE 조회 및 승인된 정산 업무만 허용한다. 영업 실적 SALES와 계정 관리 기능에는 접근을 허용하지 않는다.
- 영업팀:영업 실적 시스템 SALES 조회 및 승인된 영업 업무만 허용한다. 정산 시스템 SETTLE과 고객 DB에는 접근을 허용하지 않는다.
- 서비스 계정 batch-night:등록 기기 SRV-BATCH에서 매일 02:00에 정산 집계 프로그램을 실행하고 SETTLE을 조회하는 작업만 허용한다. 대화형 로그인, 다른 시스템 접근 및 허용된 시간 외의 실행은 차단한다.
## 스코어링 결과
- 항목별 점수:MFA 10점 / 기기 5점 / 최소권한 15점 / 세그멘테이션 0점 / 위험기반인증 0점
- 총점: 30점 / 100점
- 먼저 올릴 항목과 이유: 위험기반인증을 우선 개선한다. seoyeon 계정이 등록되지 않은 NB-7741에서 비밀번호만으로 로그인한 뒤 담당 자원이 아닌 SETTLE을 반복 조회했지만 접근이 허용된 기록이 있다. 기기·접속 위치·인증 방식·조회 패턴을 함께 평가하고, 위험 점수에 따라 추가 인증이나 차단을 적용하도록 개선한다.
