## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:
192 11000000
168 10101000
10 00001010
25 00011001
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답: 10진수 10은 2^3 + 2^1(== 8+2) 이므로 8과 2를 뜻하는 자리는 1, 나머지는 0이다. 08을 썼으므로 8자리가 출력되어야 하며 8보다 큰 수의 자리는 0이 채워진 상태로 출력된다.
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답:1010
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답: 한 옥텟이 8bits 이기 때문이다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답: 0 ~ 255 는 256개의 숫자이고 256=2^8이므로 각 마디는 8자리가 되어야 한다. 8*4=32 이므로 8bits 배열이 이어진다.
- (다-2) 32비트로 만들 수 있는 주소의 개수: 2^8^4= 4,294,967,296
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답: 한 비트(한 자리)의 경우의 수는 0과 1 두 가지이므로 2. 한 옥텟은 8비트이므로 경우의 수는 2의 8제곱 = 256.
  한 주소는 32비트, 즉 4옥텟. 옥텟 4개가 같이 사용되므로 경우의 수는 256의 4제곱. 256^4 = 4,294,967,296.
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답: 현재 지구 인류는 약 83억 1천만 명. 만들 수 있는 ip주소의 수를 뛰어넘었다. 심지어 사람은 여러 개의 전자기기를 사용하므로 주소 수가 심각하게 부족하다. 이를 해결하기 위해 하나의 ip를 여러 기기가 사용할 수 있도록  NAT과 사설 ip를 이용하게 되었다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소
#curl ifconfig.me
- (가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP: 192.168.100.64 · 1.245.252.171
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답: 주소의 첫 두 옥텟이 192.168 이므로 내 IPv4 주소는 사설 ip이다.
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답: 첫 옥텟이 10이 아니고, 첫 두 옥텟이 172.16~31도, 192.168도 아니므로 표의 어느 범위에도 들어가지 않는다. 따라서 curl로 본 주소는 공인 주소이다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답: 표의 범위 중 '172.16~31.x.x'에 들어가므로 두 주소 모두 내부망 장치로 분류해야 한다.
- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답: NAT을 통해 공인 IP로 바뀌어 나가기 때문에 특정할 수 없다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답: 정적은 일 대 일, 동적은 일 대 다 매칭이다.
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
  - 답: 동적 NAT은 하나의 공인에 여러 개의 사설을 연결할 수 있기 때문이다. PC 특정을 위해서는 공유기나 방화벽에 남은 NAT 변환 기록을 봐야 한다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답: 정적. 외부에서 접속하기 위해서는 변하지 않는 고유한 주소가 필요하기 때문이다.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수: 255.255.0.0 · 16 · 2^16= 65,536 · 2^16-2 = 65,534
- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분: 192.168 · 100.64
- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답: 1인 비트에 해당하는 자리는 망 부분, 0인 자리는 장비 부분을 기리킨다.
- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답:255.255.0.0에서 255= 128+64+32+16+8+4=2=1 이므로 이를 이용해 마스크를 2진수로 나타내면 11111111.11111111.00000000.00000000이다. 1의 수는 16개.
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답: 망 부분이 같고 장치 부분이 다르다. 두 서버는 같은 공유기를 사용하므로 같은 공용 주소를 갖고 같은 망에 속한다. 그러나 다른 컴퓨터 서버를 이용하므로 장치 부분은 다르다.
- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답: 내 마스크의 CIDR는 16이므로 주소의 첫 두 옥텟을 비교한다. 두 주소의 첫 옥텟은 192.168이므로 둘은 같은 망이다.
- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답: 세 번째 옥텟의 수가 다르므로 둘은 다른 망에 속한 IP주소가 된다.
- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답: 대상 경로가 달라지므로 중요하다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일(`warmup_3_2b.py`)의 내 주소/CIDR · 출력 세 줄:192.168.100.64/16 · 255.255.0.0
192.168.0.0
192.168.255.255
- (나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지:
첫 줄은 마스크, 두 번째 줄은 망 부분, 세 번째 줄은 브로드 캐스트 주소이다.
- (나-2) 내 주소에서 `0` · `255` 로 바뀐 마디: 255 > 왼쪽 끝에서부터 두 옥텟, 0 > 오른쪽에서부터 두 옥텟.
- (나-3) 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.
  - 답: 내 ip 주소를 2진수로 변환하면 11000000.10101000.01100000.01000000, 마스크를 2진수로 변환하면 11111111.11111111.000000000.00000000이다. 같은 자리의 숫자를 비교해 둘 다 1이면 1, 아니면 0을 내는 AND 연산을 한다. 결과는 11000000.10101000.00000000.00000000이고 이를 10진수로 변환하면 192.168.0.0이다.
- (나-4) 왜 그 마디만 바뀌고 나머지 마디는 그대로인지 망 부분과 장비 부분으로 설명하세요.
  - 답: 마스크 주소에서 망 부분은 전부 1이므로 IP주소를 2진수 변환했을 때 1인 부분은 무조건 1로, 0인 부분은 무조건 0이 나와 망 부분은 그대로 값이 보존된다. 장치 부분을 나타내는 자리의 값이 전부 0이므로 ip 주소의 값과 상관없이 무조건 0이 나와 장치 부분은 전부 0으로 바뀌게 된다.
- (다-1) `ipconfig` 의 내 기본 게이트웨이 주소가 둘째 줄과 셋째 줄 사이에 있는지(예 · 아니오):예.
- (다-2) 게이트웨이 주소가 이 범위 안에 있어야 하는 이유를 설명하세요.
  - 답: 망을 넘으려면 일단 경계에 가야 되니까 범위 안에 있어야죠. 게이트웨이가 망 밖에 있으면 다른 망 간 데이터전송이 불가능해진다.
- (다-3) 게이트웨이 주소를 둘째 줄의 네트워크 주소나 셋째 줄의 브로드캐스트 주소로 잘못 설정하면 왜 문제가 되는지, 두 주소의 역할을 들어 설명하세요.
  - 답: 마스크 주소로 설정시 컴퓨터는 네트워크 전체를 가리키는 주소로 데이터를 보내려 한다. 브로드캐스트 주소로 설정시 외부 네트워크로 나가야 할 데이터가 내부 네트워크의 모든 컴퓨터로 전달된다.

### 오전 수업 요약

- 2, 3, 4교시에 새로 알게 된 것:
format(n, "08b") : 10진수 n을 8bit 2진수로 변환.
#b : 2진수로.
#08 : 빈 자리에 0을 채워넣어 8비트로.
첫 마디가 10 || 첫 두 마디가 172.16~31 || 첫 두 마디가 192.168 == 사설 ip
사설 IP: 내 네트워크에서 밖에 못 씀. 공인 IP: 공유기 주소 또는 ISP 업체에서 산 주소. 외부와 통신할 때 이 주소로 신호를 주고 받는다. 공유기는 신호를 받아서 해당 사설 ip로 전달한다.
정적 NAT: 공유:사설 = 일 대 일, 공적 NAT : 공인 ip를 임시배정하고 접속 후에 회수. 공유:사설이 일대다도 일대일도 가능, PAT : 공유:사설=일 대 다
ip 주소에서 서브넷 마스크의 1인 자리의 숫자는 네트워크 주소, 0인 부분은 기기 주소다.
CIDR : 서브넷마스크에서 1의 수. IP주소에서 가장 왼쪽에서부터 CIDR만큼의 비트를 네트워크 주소로 본다.
ip 주소 범위에서 가장 작은 주소(기기 부분이 다 0)는 네트워크 전체 주소, 가장 큰 주소(기기 부분이 다 1)는 브로드캐스트 주소다.
게이트웨이 주소는 네트워크 주소와 브로드캐스트를 주소를 뺀 나머지에서 할당된다. 둘 중 하나가 할당되면 오류 난다.
n/25 : 네트워크를 2등분힌 다음 n번부터 블록지정 한다.
n/26 : 네트워크를 4등분한 다음 n번부터 블록지정 한다.
서로 다른 블록이 같은 기기를 자신의 블록에 지정하면 IP주소 충돌이 일어난다.
